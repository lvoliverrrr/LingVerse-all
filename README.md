# 灵界 (LingVerse) 游戏辅助脚本

这是一个针对灵界(LingVerse)网页游戏的用户脚本集合，旨在提升游戏体验和自动化一些重复性操作。

## 包含的脚本

目前包含以下4个脚本：

1. **玩家ID显示** - 显示玩家数字ID，方便添加道友
2. **神识精确数值** - 显示神识精确值而非百分比
3. **自动开藏宝图 / 自动挂机循环** - 自动开启藏宝图，并提供冥想-探索挂机原型
4. **修为简写显示** - 将修为显示为万/亿单位

---

### 1. 灵界 LingVerse 玩家ID显示 (lingverse-player-id.user.js)

这个脚本在主页状态栏、侧边栏和玩家资料面板显示当前玩家和其他玩家的数字ID，方便添加道友和拜访洞府。

#### 功能特点：
- 在顶部状态栏玩家名称后显示ID
- 在侧边栏角色信息区显示ID（境界下方）
- 在手机版状态栏显示ID
- 在查看其他玩家资料时，在名称旁显示其ID
- 点击ID可复制到剪贴板
- 复制成功显示提示

#### 安装方法：
1. 安装用户脚本管理器（如Tampermonkey、Greasemonkey或Violentmonkey）
2. 点击安装此脚本
3. 访问游戏网站即可生效

---

### 2. 灵界 LingVerse 神识精确数值显示 (lingverse-spirit-exact.user.js)

这个脚本将主页状态栏的神识百分比改回准确数值，并在使用神识时实时更新显示。

#### 功能特点：
- 将神识显示从百分比转换为精确数值（例如：120/200 而不是 60%）
- 显示神识恢复倒计时
- 实时更新神识数值
- 支持主界面和状态栏两处神识显示的更新

#### 安装方法：
1. 安装用户脚本管理器（如Tampermonkey、Greasemonkey或Violentmonkey）
2. 点击安装此脚本
3. 访问游戏网站即可生效

---

### 3. 灵界 LingVerse 自动开藏宝图 / 自动挂机循环 (lingverse-explore-helper.user.js)

这个脚本可以自动开启背包中的藏宝图，并提供外部脚本版的冥想-探索挂机循环，用于测试自动挂机体验后再决定是否合入游戏本体。

#### 功能特点：
- 自动扫描并开启背包中的藏宝图
- 支持批量处理，可设置每次开启的数量
- 遇到战斗时可自动雇用护道者
- 提供气运状态显示和统计信息
- 可配置护道者雇佣条件（最高费用、最低攻击力等）
- 支持多种作战模式和优先级设置
- 支持自定义冥想时长、最低神识阈值和自动探索倍率
- 自动探索运行或恢复挂起时，如果神识低于阈值、页面提示神识不足或长时间无进展，会主动回冥想；复制状态会说明当前神识、单次消耗、倍率所需神识和阈值
- 自动探索接口返回“体力不足/精力不足/灵力不足”等明确资源不足错误时，也会按神识不足同样回冥想；普通接口异常仍会暂停等待人工确认
- 启动自动探索入口时如果页面直接提示资源不足，会短暂标记为“探索启动资源不足”，下一轮统一走回冥想决策，避免旧缓存显示神识够时反复启动失败
- 自动探索进展会同时参考页面探索/战斗/收入日志变化；如果 `_autoExploreCount` 没刷新但真实游戏日志还在更新，不会误判为卡住回冥想；判断来源优先限定在游戏日志容器，避免聊天或说明里的“探索/收入”文字误刷新进度
- 如果自动探索开关仍显示勾选，但游戏内部运行/恢复标志都已关闭，挂机会识别为“开关失配”并重新启动自动探索，避免只看 UI 开关而长期空等
- 高倍率探索会按“单次消耗 × 探索倍率”判断整组神识是否足够；例如单次 10 神识的 50 倍探索需要 500 神识，不足时先回冥想而不是反复启动失败
- 探索按钮禁用但页面没有给出神识不足文字时，只要当前神识已经低于阈值或单次探索消耗，也会回冥想，避免低神识空等
- 自动挂机每轮快照会优先刷新玩家信息，失败时才回退页面缓存；这样神识刚被探索消耗到 20 以下时，能更快回冥想，减少旧缓存误判继续探索
- 如果玩家接口和 `_lastPlayerData` 都短暂不可用，挂机快照会只读页面状态栏 `#statSpirit` 和探索按钮 `#exploreBtn`，补齐神识上限与单次探索消耗，避免刚刷新页面时误判缺少资源数据
- 页面冥想条可见但玩家缓存滞后时，复制状态会显示“冥想兜底”，说明冥想条恢复神识、缓存神识和估算神识，方便判断为什么提前收功
- 支持自定义事件/复活后的恢复窗口，适配慢网络或战斗结算较慢的账号
- 自动迎战、自动护道、奇遇/陌生道友处理后会进入同一个恢复窗口，神识足够时继续探索、神识不足时回冥想；复制状态会显示剩余秒数和恢复后的动作倾向；恢复窗口只在 AFK 循环开启时主动安排下一轮检查，避免手动调试或面板关闭时后台自行推进
- 结束冥想成功后会进入收功恢复窗口，短时间内优先尝试恢复自动探索，避免玩家缓存滞后时又立刻回冥想
- 当页面可见冥想条但玩家缓存尚未同步为冥想中，复制状态会显示“冥想同步”提示，并按冥想条恢复神识估算是否该收功
- 冥想条显示恢复神识时，复制状态会显示“冥想预计”，估算当前有效神识和按计划收功时的大致神识，方便测试 140 分钟或自定义冥想时长是否合适
- 冥想条恢复量已经让估算神识超过上限时，复制状态会显示“冥想溢出”，说明大约浪费了多少神识，方便改短自定义冥想时间或及时收功探索
- 冥想溢出时会按当前恢复速度估算“约多少分钟可满识”和本次超过满识点多久，帮助测试者把固定冥想分钟调得更接近当前账号恢复速度
- 复制状态会显示“探索续航”，按当前神识、单次消耗和配置倍率估算还能跑几组；冥想中会使用已恢复神识和计划收功神识估算，高倍率不足一组时同时给出约等于多少次 1 倍探索，方便判断是否该继续冥想
- 收功恢复窗口内，如果探索入口短暂显示不可用但页面没有明确“神识不足/体力不足”原因，会继续尝试恢复自动探索；明确提示神识不足时仍会回冥想
- 如果恢复窗口反复尝试重启自动探索但没有成功，复制状态会在“诊断归因”里显示事件/复活恢复后未能重启探索和自动探索入口失败原因
- 如果收功恢复窗口反复尝试重启自动探索但没有成功，复制状态会显示“收功后未能重启探索”和失败入口，方便判断是神识刷新、倍率控件还是自动探索入口问题
- 支持稳妥 1 倍 / 护道 1 倍 / 富裕 50 倍挂机预设，套用预设不会自动启动挂机，并会同步自动商人安全策略
- 复制状态会显示当前配置是否匹配稳妥 1 倍、护道 1 倍或富裕 50 倍预设；偏离时会指出最接近的预设和关键差异，方便测试者复现同一挂机模式
- 预设匹配状态会同时检查自动商人策略；如果 AFK 开关像富裕 50 倍但自动商人被关掉，状态会提示“自动商人应开启”
- 富裕 50 倍预设默认带单轮资源保险丝：复活 1 次、用符 3 场、用丹 1 次；也可自定义，`0` 表示不限
- 富裕模式启动自动探索前会读回页面实际倍率；如果目标 50 倍但页面仍是 1 倍，会停止启动并在复制状态里显示目标/实际倍率，避免假装按 50 倍挂机；涅槃重生丹也会等倍率确认后才尝试使用，减少资源浪费；调用自动探索入口后还会确认页面运行标志已开启，避免打坐/事件/低神识等阻塞时误报已启动
- 支持自动购买云游商人最高价商品
- 暴露 `LingVerseAutoMapTestHooks.showPanel()` / `getPanelState()`，方便 Agent Browser CLI 直接打开助手面板并读回版本、AFK 和商人配置，不需要误点游戏资源按钮
- 云游商人商品接口未提供 `index` 时，会用商品数组位置作为购买 index，避免识别到最高价商品后传空 index 卡住
- 云游商人接口为空或读取失败但弹窗已渲染商品时，会从可见商人弹窗 DOM 只读解析商品名、价格和购买 index，再按最高价商品继续购买
- 云游商人已确认没有可买商品时，可自动离开并恢复挂机；API 读取失败这类不确定状态不会强退，避免错过临时未读出的商品
- 如果页面残留商人状态但接口确认“没有遇到云游商人”，会清理残留商人窗口并恢复挂机，避免下一轮反复卡在商人读取失败
- 云游商人“只在自动探索/挂机循环时处理”会把已启动的 AFK 循环也视为自动化上下文，减少原生恢复标记缺失时卡商人；未启动挂机且未自动探索时仍保护手动购物
- 通过页面函数触发云游商人购买后，也会执行商人窗口清理、日志/玩家信息刷新、自动探索恢复兜底，并打开 AFK 事件恢复窗口；如果购买已触发但商人窗口持续未关闭，复制状态会显示专属诊断归因
- 云游商人最高价商品购买失败且页面/接口明确提示灵石、余额等货币不足时，可自动离开商人并恢复挂机；普通购买失败仍会停留并报告，避免误丢可处理商品
- 自动商人购买和离开会优先走游戏 API，能读取真实 `code/message`；只有 API 不可用时才回退页面函数，避免页面函数吞掉失败后误判为已购买
- 复制状态会显示云游商人购买结果、商品名、价格、触发来源、脱敏失败消息和下一步建议，方便确认是否卡在商人窗口
- 商人、遭遇、奇遇、陌生道友和冥想条检测会同时检查 `hidden` class、`display:none`、`visibility:hidden`、`aria-hidden` 和零尺寸，减少隐藏 DOM 残留导致的误阻塞
- 支持 opt-in 的陌生道友邂逅婉拒、遭遇前自动护道、死亡复活、战斗用符、涅槃重生丹、奇遇固定选择
- 复制状态会显示陌生道友自动婉拒结果、触发来源、脱敏失败消息和下一步建议，方便确认是否卡在邂逅弹窗关闭入口
- 如果陌生道友自动婉拒重复执行但弹窗没有关闭，复制状态会在“诊断归因”里显示“陌生道友自动婉拒后仍未关闭”，方便手动处理或反馈弹窗结构
- 陌生道友自动婉拒只处理当前可见弹窗；隐藏残留的 PVP/邀请/会话窗口和按钮不会被当作可操作入口，减少长跑中误点旧弹窗
- 陌生道友婉拒入口调用后会确认弹窗已经关闭；如果仍可见，不会进入事件恢复窗口，避免误接自动探索
- 遭遇前自动护道可独立于自动迎战开启，会优先读取游戏当前自动护道设置；同一次遭遇只尝试一次，失败后暂停等待手动处理，复制状态会用中文显示护道结果、失败原因和处理建议
- 遭遇前自动护道会优先调用游戏页面的自动护道函数或护道接口，读取真实成功/失败结果；只有这些入口不可用时才回退按钮，避免只是点到护道按钮/弹窗就误报已雇护道
- 如果游戏遭遇面板显示自动雇护道正在重试/处理中，助手会等待游戏护道结算，不会重复触发护道入口
- 护道 1 倍模式如果同一遭遇已经尝试过自动护道，重复等待诊断会说明“本遭遇已尝试自动护道，避免重复扣费”，方便测试者手动处理而不是怀疑脚本漏点
- 批量探索遭遇不能雇护道；如果手动把“自动护道”和 5/10/20/50 倍探索组合，AFK 遭遇处理会跳过护道并在风险预检/复制状态里提示改用 1 倍护道或富裕 50 倍战斗链路
- 死亡状态优先级高于残留遭遇/商人/奇遇面板；开启自动复活时会先复活，确认死亡状态解除后再进入恢复窗口
- 如果复活入口返回但页面仍显示死亡，会记录“自动复活未确认”，不直接恢复 50 倍探索，并把这次入口调用计入本轮复活尝试，减少重复扣资源
- 战斗用符可配置 family 顺序/白名单，例如 `ghost,fire,shield`；留空则按原逻辑选择最高品质 family
- 同一次遭遇只会处理一次战斗用符；没符会跳过并记住，避免重复扫背包或反复消耗符箓
- 复制状态/摘要会只读背包做富裕资源预检，提示战斗符箓 family 数和史诗+涅槃重生丹是否可用
- 奇遇链默认暂停；可按全局第 N 项或 `adventureId -> choiceIndex` 策略表固定选择，未知奇遇状态会显示 ID、步骤、选项文本和可复制的策略候选行
- 奇遇默认暂停时不会自动选择剧情分支，但已完成且只剩结束/关闭按钮的奇遇可自动关闭收尾；该行为可关闭，方便保守测试
- 复制状态会显示奇遇自动选择/关闭结果、奇遇 ID、选中的第几项、选项文本、触发来源、脱敏失败消息和下一步建议，方便确认是否卡在策略或按钮入口
- 如果奇遇自动选择重复执行但页面没有推进，复制状态会在“诊断归因”里显示奇遇 ID、自动选择的第几项和选项文本，方便修正策略或手动处理
- 同一个奇遇 ID、步骤、总步数和选项已经触发过时，助手会暂停重复点击并等待页面推进；状态会显示“本步已触发自动选择”，避免未变化的奇遇页被连续点击
- 奇遇自动选择入口调用后会确认页面是否推进；如果仍停在同一步，会记录自动选择失败且不进入事件恢复窗口，避免误接探索
- 已完成奇遇自动关闭后也会确认面板是否真的消失；如果关闭按钮无效或页面仍卡着，会记录自动关闭失败且不进入事件恢复窗口
- 检测到“灵界已更新新版本”提示时默认暂停并写入状态报告；可显式开启自动刷新页面
- 复制状态在游戏更新提示出现时会显示 helper 版本和“先刷新页面/重载扩展”的环境提示，方便排查测试者是否加载到最新版
- 扩展加载器会把扩展版本写入页面并给注入脚本加版本参数；复制状态发现 helper/扩展版本不一致时会提示重载扩展并刷新页面
- 如果页面 helper 和面板初始化已经是新版，但扩展 dataset 仍停在旧版本，复制状态会显示“页面已加载新版，扩展提示待下次重载统一”，避免误导测试者反复打开扩展页
- 如果扩展只留下“已注入”标记但 helper/面板没有真正初始化，加载器会重新注入脚本，减少刷新后看不到挂机面板的半注入状态
- 复制状态会区分 helper 顶层版本和面板初始化版本；如果扩展重载后页面仍保留旧面板，会提示刷新页面确认新版面板
- 混天典狱、天道禁闭等不可安全跳过状态会显示“硬停:”和“硬停建议:”，明确脚本不会自动跳过、自动点击或消耗资源
- 自动挂机面板显示当前决策、上次动作和下次检查时间，方便测试者直接判断脚本是在等待、检查还是处理事件
- 复制状态会显示挂机阶段，例如冥想已过/剩余、满神识提前结束、探索倍率和卡住判定
- 如果页面可见 `#meditationBar` 冥想条但玩家缓存或冥想接口状态不同步，挂机快照会用冥想条文本兜底识别“冥想中”和已冥想时长；即使冥想条被浏览器压成一行，也会避开“最长12小时”解析真实已冥想时长，减少到点不收功
- 冥想条里的“恢复 ... 识”也会作为只读兜底；当缓存神识加恢复神识已达到上限时，会走原有“神识已满”收功决策
- 复制状态会显示进入/结束冥想的执行结果、触发来源、触发原因（神识已满或冥想时长已到）、已冥想时长、计划分钟、脱敏失败消息和下一步建议，方便验证自定义 140 分钟循环是否真的收功
- 进入冥想入口调用后会再次确认页面已经显示冥想中；如果仍未进入冥想，会记录失败并让下一轮继续诊断
- 结束冥想入口调用后会再次确认页面不再显示冥想中；如果仍在冥想，不会进入收功恢复窗口，避免误接自动探索
- 复制状态会显示自动探索启动结果、探索倍率、触发来源、脱敏失败消息和下一步建议，方便判断是否卡在倍率控件或自动探索入口；自动探索疑似不动而回冥想时，会同时显示当前卡住判定秒数
- 复制状态会显示自动复活结果、触发来源、脱敏失败消息和下一步建议；复活未确认时会明确提示不会进入恢复窗口，方便富裕 50 倍测试者确认战死后是否卡在复活阶段
- 复制状态会显示战斗用符结果、成功/失败 family 数、符箓面板是否关闭、脱敏失败消息和下一步建议，方便富裕 50 倍测试者确认是否卡在用符阶段
- 如果用符后符箓面板没有关闭，自动迎战会在同一轮内立刻停住并在状态里显示“符箓面板未关闭”，避免面板遮挡时误点或重复调用迎战；下一轮快照确认残留符窗仍可见时，会先尝试关闭符窗再恢复迎战，旧失败记录不会永久卡住
- 如果本次已选中的战斗符全部使用失败，自动迎战会暂停并在迎战建议里显示脱敏失败消息；没有可用符箓时仍按“跳过用符”继续后续逻辑
- 复制状态会显示自动迎战结果、触发来源、同遭遇去重状态、符箓面板阻断/恢复状态和失败建议，方便富裕 50 倍测试者确认用符后是否真的进入迎战且不会重复点击
- 自动迎战会优先走 `/api/game/combat-choice` 读取真实返回码；页面函数和按钮只作为 API 不可用时的兜底，避免按钮点击或页面 toast 被误记为已迎战
- 复制状态会显示涅槃重生丹决策/执行结果、丹药名、品质、脱敏失败消息和下一步建议，方便确认富裕 50 倍是否卡在用丹阶段
- 涅槃重生丹入口返回成功后会确认五行通灵效果是否出现；未确认时会报告“用丹未确认”且不计入本轮用丹次数，避免误以为已经消耗成功后继续 50 倍链路
- 自动挂机面板显示高风险动作预检，汇总迎战、护道、复活、用符、用丹、道友婉拒、奇遇自动选择和单轮资源上限的状态与警告
- 面板支持复制可读挂机状态报告，方便测试者先确认版本、风险、阻塞、资源用量和重复等待诊断归因
- 可读状态报告会直接显示自动商人配置，包含是否开启、是否限定自动探索/挂机循环、购买延迟、无商品离开和购买后卡窗离开
- 自动挂机重复等待或自动动作反复未推进时，会把最近一次脱敏卡点快照保存到本地，并保留最近 5 条不同卡点历史；面板可“复制最近卡点”或“复制卡点历史”，Agent 也可用 `LingVerseAutoMapTestHooks.getLastAfkIssueSnapshot()` / `getAfkIssueHistory()` 读回
- 面板支持复制/导入挂机配置包，测试者可以共享固定挂机参数和自动商人策略，导入时会自动关闭启动状态
- 面板支持粘贴脱敏摘要生成“摘要回放”，把测试者反馈还原成决策、阻塞、风险开关和奇遇策略表，并可一键把候选策略行导入本地策略表；也能从可读状态里的 `奇遇策略: 456=2 / 789=1` 或 `#456 · 第2项` 这类文本提取策略
- 支持记录最近奇遇样本；即使奇遇弹窗已经关闭，复制状态也能带出最近的奇遇 ID、步骤、选项和可导入策略候选，方便众测沉淀事件策略
- 支持复制挂机调试脱敏摘要，包含最近决策、等待诊断归因、日志、最近奇遇样本、用丹/用符/迎战/护道尝试结果；未知等待或自动动作反复未推进时，可读状态会追加最近一条脱敏现场日志，方便测试者反馈停住原因和未知事件

#### 使用方法：
1. 安装脚本后，在游戏侧边栏会出现"自动开图"按钮
2. 点击按钮打开控制面板
3. 设置所需参数（开启数量、护道者配置等）
4. 点击"启动"开始自动化运行
5. 点击"停止"结束运行
6. 如果只是报当前情况，点击"复制状态"；如果需要开发者复现问题，点击"复制摘要"发送脱敏 JSON；如果挂机已经卡过但当时没复制，点击"复制最近卡点"或"复制卡点历史"

#### 配置选项：
- 每次最多开启：设置单次最大开启数量
- 批量数量：设置批量处理的大小（1-10）
- 开启间隔：设置每次开启之间的延迟
- 自动雇护道：启用或禁用自动雇用护道者
- 雇佣费用限制：设置最高雇佣费
- 攻击力要求：设置最低攻击力要求
- 作战模式：选择协同作战或独立作战
- 妖兽设置：设置妖兽的生命值和攻击力限制
- 自动挂机循环：冥想分钟、最低神识、探索倍数、倍率所需神识、卡住判定、恢复窗口
- 挂机预设：稳妥 1 倍关闭资源消耗动作；护道 1 倍只开启遭遇前自动护道；富裕 50 倍开启迎战、复活、用符、涅槃重生丹；三种预设都会把自动商人重置为最高价购买、仅自动探索/挂机循环处理、无商品/购买后卡窗/灵石不足自动离开
- 富裕模式开关：自动迎战、自动复活、自动用符、自动使用涅槃重生丹
- 资源上限：单次启动后的复活次数、用符遭遇数、用丹次数，`0` 表示不限
- 战斗符箓：最多 family 数、每类数量、可选 family 顺序/白名单
- 富裕资源预检：复制状态/摘要时只读背包，检查战斗符箓 family 和涅槃重生丹，不会使用物品
- 自动商人：购买最高价商品、购买延迟、仅自动探索/挂机循环时处理、无可买商品时自动离开、购买后窗口未关闭时自动离开、灵石不足时自动离开、商人状态残留时清理并恢复挂机
- 事件策略：陌生道友邂逅自动婉拒、奇遇链暂停/固定选择/按 ID 策略、已完成奇遇自动关闭收尾
- 页面更新：游戏提示新版本时默认等待；可开启自动刷新页面
- 实时状态：显示当前决策、上次动作和下次检查时间
- 风险预检：显示 7 个高风险动作的开关状态、护道参数、用符/用丹参数、资源上限和配置警告；自动护道搭配批量探索时会提示“批量探索遭遇不能雇护道”
- 状态报告：复制一段可读文本，包含版本、环境提示、当前决策、神识、阻塞、阶段/恢复剩余时间、冥想条兜底状态、冥想预计、冥想溢出、冥想调时、探索续航、预设匹配/偏离、自动商人配置、自动探索开关失配、回冥想原因、倍率所需神识、风险、冥想执行结果/建议、商人购买结果/建议、探索启动结果/建议、复活结果/建议、护道结果/建议、用符结果/建议、迎战结果/建议、用丹结果/建议、当前/最近奇遇样本、资源用量、重复等待诊断归因和必要时的最近现场日志；符箓面板未关闭时会在迎战行明确阻断原因，并在后续快照确认残留符窗可见时尝试关闭后恢复迎战
- 配置包：复制当前挂机配置和自动商人设置，或导入他人的配置包；导入后不会自动启动挂机
- 摘要回放：粘贴调试摘要 JSON，生成问题回放视图和可复制的奇遇策略行；也可导入策略行，导入时只改本地配置且不会启动挂机
- 最近卡点：挂机循环自动保存最近一次有效重复等待诊断，保存内容包含脱敏摘要和可读报告，可从面板复制或从测试 hook 读回；卡点历史保留最近 5 条不同卡点，普通巡检不会写入
- 调试反馈：复制当前挂机脱敏摘要，包含神识、阻塞事件、当前/最近奇遇 ID 与选项、下一步决策、最近决策/日志、重复等待诊断归因、高风险开关状态、预设匹配状态、自动商人配置、资源上限用量、富裕资源预检、冥想执行尝试、商人购买尝试、富裕模式用丹尝试原因、战斗用符尝试结果和符箓面板关闭状态、自动迎战触发来源/失败原因和护道尝试结果；URL query/hash 和长日志会自动压缩/脱敏

### 4. 灵界 LingVerse 修为简写显示 (lingverse-cultivation-compact.user.js)

这个脚本将修为数值简化为"几千万几亿"格式，解决手机端显示不全的问题。

#### 功能特点：
- 将大数字修为简化为中文单位（万/亿）
- 手机端自动启用简写显示
- 桌面端修为≥1000万时启用简写
- 鼠标悬停显示完整数值
- Hook游戏原生数据更新，零性能开销

#### 显示示例：
- 20,569,239 / 30,000,000 → 2056.9万 / 3000万
- 150,000,000 / 300,000,000 → 1.5亿 / 3亿
- 1,234,567,890 → 12.34亿

#### 安装方法：
1. 安装用户脚本管理器（如Tampermonkey、Greasemonkey或Violentmonkey）
2. 点击安装此脚本
3. 访问游戏网站即可生效

## 系统要求

- 浏览器支持用户脚本（如Chrome、Firefox、Edge等）
- 已安装用户脚本管理器（Tampermonkey推荐）

## 注意事项

1. 使用这些脚本时请遵守游戏的服务条款
2. 脚本仅为辅助工具，不保证完全无风险
3. 在更新脚本前建议备份个人配置
4. 如遇到问题，请检查脚本版本是否为最新
